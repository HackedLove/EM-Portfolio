SOP-104: Troubleshooting Network Share Access & VLAN Misconfigurations

Target Audience: IT Support Specialists & Help Desk Technicians | Supported OS: Windows 10/11

1. Purpose & Scope

This standard operating procedure guides technicians through diagnosing why an office-based user cannot access network share drives, focusing on environmental changes, VLAN assignment mismatches, and Layer 3 Access Control Lists (ACLs).

2. Step-by-Step Troubleshooting Workflow

  1. Initial User Interview: Confirm user identity and exact error message. Ask targeted environmental questions: Are you working from your assigned desk, or have you moved to a temporary office or conference room?
  2. Endpoint IP & Gateway Validation: Connect remotely to the workstation. Open the terminal and run ipconfig to verify the assigned IP address and default gateway.
  3. Network Path & Server Reachability: Test communication using ping to the local default gateway, then ping the target file server's IP address. A "Destination unreachable" response indicates a routing or firewall block.
  4. Switch Port & VLAN Verification: Check network documentation and access the switch CLI using show interface [port] switchport to verify physical port VLAN membership.
  5. Layer 3 ACL Policy Check: Inspect switch or router access lists using show access-list to determine if traffic is explicitly blocked between source and destination subnets.

3. Resolution & Verification

Root Cause: User was relocated to a temporary office associated with an isolated VLAN that lacked explicit ACL permissions to reach server subnets.

Verification: Have the user re-map or navigate to the network share path (e.g., \\HR_FILE01), open a test file, and confirm read/write access.
