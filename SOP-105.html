SOP-105: Troubleshooting Intermittent Network Connectivity & Duplicate IP Addresses

Target Audience: IT Support Specialists & Help Desk Technicians

Supported OS: Windows 10 / Windows 11

Estimated Time: 15 - 20 minutes

Prerequisites: Remote support tool access (RDP/Screen Share), switch CLI read access, and network topology documentation.

Purpose

This Standard Operating Procedure guides technicians through troubleshooting intermittent network connectivity where a user's connection drops or stalls during the day, with a focus on DHCP scope exclusions and duplicate IP address conflicts with static network devices.

Step-by-Step Troubleshooting Workflow

1. Initial User Interview & Scope Verification (3 min)

Confirm the employee's identity and ask environmental questions: Are you working from your assigned desk? Is anyone else experiencing the same issue? Has anything changed since your last login, such as recent updates, office maintenance, or work on nearby equipment or printers? What specific services or resources (internet, email, network shares) are failing?

Verification: Technician documents the user's physical location, affected apps/shares, and any recent hardware or network changes.

2. Ethernet Cable, Switch & Port Connection (3 min)

Connect remotely to the workstation and check network topology documentation to identify the switch and port serving the user's jack. On the switch CLI, inspect port status and error counters (for example, show interfaces fastEthernet 0/10 or show interfaces status).

Verification: Port is up/connected with no abnormal interface drops, CRC errors, or link flaps.

3. Endpoint IP & Gateway Validation (4 min)

Open Command Prompt on the employee's machine and run ipconfig. Record the assigned IPv4 address, subnet mask, and default gateway, then test reachability with ping <gateway IP>.

Verification: Workstation has a valid IPv4 address on the expected subnet and receives replies from the default gateway.

4. Duplicate IP Address & MAC Trace Check (5 min)

End the remote session and have the user unplug the Ethernet cable from their workstation. From another machine on the same subnet, clear the ARP cache (arp -d * in an elevated prompt), run ping <workstation IP>, and check arp -a to capture the responding MAC address. Trace that MAC address on the switch (for example, show mac address-table address <MAC>).

Verification: Replies to the workstation's IP continue after the cable is unplugged, and the MAC address maps to another device on a switch port (such as a printer on Fa0/20).

Resolution & Remediation

  • Root Cause: A network device (such as an office printer serviced earlier in the day) uses a static IP address (for example, 192.168.40.50) that was not excluded from the DHCP scope. When the device was offline, DHCP leased that address to the user's workstation, causing IP conflicts and intermittent drops once the static device came back online.
  • Fix: Exclude the static IP address (such as 192.168.40.50) from the DHCP server scope, have the user reconnect their Ethernet cable, reconnect remotely, and run ipconfig /release followed by ipconfig /renew.

How to Verify Success

Confirm the workstation received a new, non-conflicting IP lease via ipconfig, ping the default gateway and the static device (such as the printer), and test internal shares. Have the user confirm internet access, email (Outlook), and shared folder access are working normally.
